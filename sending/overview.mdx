`@webhooks/sdk` is the producer side of the Standard Webhooks stack. You define a map of typed events, tell the SDK who should receive each one, configure a signing secret, and call `wh.send()`. The SDK takes care of signing every request with HMAC-SHA256, delivering it over HTTP, and reporting back what happened — per subscriber, not just in aggregate.

## Core concepts

Before diving into code, here is a quick map of the four ideas that wire everything together.

**EventMap** — an object whose keys are event type names (`"invoice.paid"`) and whose values are [Standard Schema](https://standardschema.dev/) validators (Zod v4, Valibot, ArkType, and others all implement the spec). The schema for each event describes the `data` payload. TypeScript correlates the key and schema at compile time, so passing the wrong shape to `wh.send()` is a type error.

**Subscriber / SubscriberResolver** — a subscriber is `{ url, secret? }`. You can supply a static array for internal setups, or a resolver function that receives the event name, subject, and validated data and returns the right set of endpoints from your database. Secrets on individual subscribers override the top-level signing secret.

**Signing secret** — a string configured at the top level via `signing: { secret }`. Secrets prefixed with `whsec_` are treated as base64-encoded keys (Standard Webhooks format); anything else is used as raw UTF-8. Every outgoing request is signed whether you use direct or outbox delivery.

**Delivery mode** — `direct()` delivers inline from `send()` with in-process retries; `outbox(adapter)` writes rows to durable storage and a separate worker delivers them. The type system enforces the distinction: outbox-only methods like `with(tx)` and `worker()` are compile errors when the SDK is configured for direct delivery.

## Minimal working example

The snippet below is the fastest path from zero to a working webhook sender. It uses `direct()` delivery (the default) and a Zod schema for the event payload.

```typescript
import { webhooks, direct } from "@webhooks/sdk";
import { z } from "zod";

const events = {
  "invoice.paid": z.object({ invoiceId: z.string(), amountCents: z.number() }),
  "user.created":  z.object({ userId: z.string(), email: z.string() }),
};

const wh = webhooks({
  events,
  subscribers: async ({ event, subject }) =>
    db
      .select({ url: subs.url, secret: subs.secret })
      .from(subs)
      .where(and(eq(subs.subject, subject), arrayContains(subs.events, [event]))),
  signing: { secret: process.env.WEBHOOK_SECRET! },
  delivery: direct({ maxAttempts: 5 }),
});

const result = await wh.send({
  event: "invoice.paid",
  subject: "acct_42",
  data: { invoiceId: "inv_1", amountCents: 4200 },
});

if (!result.ok) {
  console.error("send failed:", result.error);
} else {
  console.log("event id:", result.value.eventId);
  for (const d of result.value.deliveries) {
    console.log(d.url, d.delivered ? "✓" : "✗", d.status ?? d.error);
  }
}
```

## Understanding `Result<T>`

Every call to `wh.send()` returns `Promise<Result<T>>` — a discriminated union with two shapes:

```typescript
type Result<T> =
  | { ok: true;  value: T }
  | { ok: false; error: string }
```

**`result.ok === false`** means something prevented any delivery from being attempted. These are fatal, setup-level failures: schema validation rejected the payload, the event type is not in your `events` map, the payload is not JSON-serializable, the subscriber resolver threw, no signing secret was found for a subscriber, or the secret has an invalid `whsec_` prefix.

**`result.ok === true`** means delivery was attempted for every subscriber. The top-level result does not tell you whether each subscriber succeeded — that information lives in `result.value.deliveries` (direct mode) or `result.value.enqueued` (outbox mode). A subscriber that exhausted all retries without a 2xx response will have `delivered: false` in its `DeliveryOutcome`, but `result.ok` is still `true`.

```typescript
if (result.ok) {
  // Top level succeeded — but check individual deliveries
  const failed = result.value.deliveries.filter((d) => !d.delivered);
  if (failed.length > 0) {
    console.warn("some subscribers did not receive the event:", failed);
  }
}
```

This two-level design keeps fatal misconfiguration separate from expected HTTP turbulence, so you can handle each appropriately.
